## 1. 分阶段开发计划

### 1.1 排期假设与里程碑

工作量为单名熟悉 C++ 和三维开发的开发者、可使用 AI 辅助、按本首版范围顺序实施的粗估；不构成固定交付日期。正式排期在 P0 完成后校正。估算不包含复杂模型修复、美术资源生产、模型训练和跨平台适配。

| 阶段 | 版本结果 | 主要交付 | 依赖 | 粗估人日 |
| --- | --- | --- | --- | --- |
| P0 技术验证 | 可运行的技术样例 | 版本锁定、原生扩展、最小骨架、精确采样、GLB/FBX 路线和 UE 回读 | 无 | 3–5 |
| P1 文档与木偶 | 可保存的摆姿势工具 | 工程文档、命令、撤销重做、标准木偶、FK 和关节限制 | P0 | 5–8 |
| P2 动画制作 | v0.1 木偶动画版 | 时间轴、关键帧、插值、双骨段 IK、接触和基础动作库 | P1 | 7–12 |
| P3 AI 编辑 | v0.2 AI 辅助版 | MCP、能力发现、批量事务、姿势读取、预览和诊断 | P2 | 4–7 |
| P4 已有骨架适配 | v0.3 角色复用版 | 运行时角色导入、骨链映射、参考姿势校准和重定向 | P2、P3 接口约定 | 7–12 |
| P5 无骨架绑定 | v0.4 绑定版 | 关节定位、骨架生成、自动权重、修正画笔和诊断姿势 | P4 | 15–25 |
| P6 批量交付 | v0.5 导出版 | 统一导出器、预设、任务队列、结果清单和 UE 兼容验证 | P0 出口验证、P4、P5 | 6–10 |
| P7 首版稳定 | v1.0 | 恢复、打包、文档、性能修整及端到端交付样例 | P1–P6 | 5–8 |

合计约 52–87 人日。考虑约 25% 的返工和兼容缓冲，预算约 65–110 人日；按单人每周 5 个工作日约为 13–22 周。若 P0 暴露导出或蒙皮算法风险，先修订工作量与阶段范围，不压缩验收。

P2 可用于制作木偶动作；P3 可用 AI 修改动作；P4 可将动作应用到已有骨架角色。P5 和 P6 补齐用户最初设想中的无骨架模型绑定与统一批量输出，P7 才称完整首版。

### 1.2 P0：技术验证

交付任务：

1. 固定 Godot 稳定版、godot-cpp、C++ 编译器和构建配置；记录依赖及许可。
2. 建立最小独立工程和 C++ 扩展，在打包应用内读写一个骨架姿势。
3. 验证 0.80 秒片段在 24/30/60 FPS 下的时间码、端点和采样结果。
4. 验证用户目录中的 GLB 运行时导入、骨架动画预览和 GLB 输出。
5. 用少量骨骼和带权重测试网格验证 FBX 输出，在 UE 中读取骨架、蒙皮和动画。
6. 检查首选 FBX SDK 的发行条件、安装依赖和打包方式；选择并记录最终出口路线。
7. 记录目标硬件与简短预览性能数据，明确线程和图像生成方式。

简单验收：打包后的软件独立启动，能读取测试角色、修改姿势、保存一个短动作，并在 UE 中看到一致的测试动作和蒙皮。尚不能满足时，保留技术样例及失败记录，先解决对应阻塞再进入正式功能开发。

### 1.3 P1：文档与木偶控制

交付任务：

1. 实现稳定资源 ID、文档修订、基础序列化和命令事务。
2. 实现撤销、重做和拖拽预览提交；接口契约从此阶段建立。
3. 显示 23 节点标准木偶，完成选择、旋转、根节点和骨盆控制。
4. 实现轴可视化、自然/宽松预设、严格/提示模式和实际值反馈。
5. 实现姿势保存、复制、复位和基础对称操作。

简单验收：摆出持剑姿势，尝试超出限制的膝部旋转，确认受限结果可见；撤销后恢复，再保存重开获得同一姿势。

### 1.4 P2：关键帧与自动过渡

交付任务：

1. 实现时间轴、轨道选择、关键帧新增/移动/复制/删除和自动关键帧状态。
2. 完成保持、线性和平滑过渡；先提供基础曲线调节，再补细粒度切线。
3. 完成双骨段 IK、肘膝方向、脚部接触区间与根运动模式。
4. 完成基础动作库、姿势库、循环预览和简单缩略图。
5. 调用 P0 的 GLB 出口完成单动作输出；后续复用同一出口适配器。

简单验收：用少量关键姿势制作横斩，修改蓄力和挥击间距后能看到节奏变化；下蹲动作固定支撑脚；保存后重开仍可编辑并导出。

### 1.5 P3：AI 接口与反馈

当前进度：以下第 1–3 项的基础功能已实现；第 4 项已实现姿势回读、多视角独立图片和已存关键帧约束检查。第 5 项以及完整诊断、拼图仍待后续开发，不将 P3 全部标为完成。骨架编辑器的可视界面后续接入当前约束命令服务。

交付任务：

1. 建立 MCP stdio 适配器和本机命令连接，完成能力与版本发现。
2. 暴露读取骨架、新建片段、批量关键帧修改、约束设置和保存等工具。
3. 实现修订冲突、请求去重、原子事务与明确撤销目标。
4. 实现指定时刻的姿势数据、多视角拼图和基础诊断。
5. 实现后台任务状态、显式取消和界面操作记录。

简单验收：通过工具新建横斩并生成预览，再执行“延长蓄力、加快挥击”的结构化修改；同一请求重试不能重复应用；人工插入编辑后，旧修订写入应返回冲突；一组 AI 修改可整体撤销。

### 1.6 P4：已有骨架角色复用

交付任务：

1. 导入真实人形角色，保留骨骼名称、层级、参考姿势和蒙皮。
2. 完成手动语义映射和骨链配置，以及自动候选建议。
3. 实现参考姿势校准、比例适配、脚部接触修正和单手道具握持。
4. 保存角色适配配置与角色动作修正；扩展对应 AI 工具。
5. 通过既有导出适配器输出单个目标角色动作，完成一次 UE 导入验证。

简单验收：同一待机、下蹲或挥剑动作能在两个比例不同的已有骨架角色上预览；修正其中一个角色不修改源动作；确认输出骨架与目标保持约定关系。

### 1.7 P5：无骨骼模型绑定

本阶段分成两个可分别检查的交付批次，控制风险集中在蒙皮质量。

P5-A：定位与生成。

1. 实现正侧面关节点定位、对称、深度微调和定位点保存。
2. 生成目标角色骨架，检查骨长、局部轴及绑定矩阵。
3. 为刚性测试部件提供临时单骨影响预览，确认骨架方向和层级正确；该预览不能当作柔性蒙皮完成。

P5-B：蒙皮与修正。

1. 实现初始权重算法、部件和区域约束、归一化及影响数限制。
2. 实现权重颜色显示、区域选择、增减/设定/平滑、锁定及笔画撤销。
3. 实现诊断姿势、失败项定位、保存与重算流程。
4. 扩展 AI 定位与生成权重任务，返回进度和实际结果。

简单验收：一个无骨骼标准人形模型经手动定位、自动权重和少量局部修正后，完成举手、屈肘和下蹲预览；不存在未分配顶点或明显跨肢体串权重；修改绑定时旧后台结果不能覆盖新定位。

### 1.8 P6：批量导出

交付任务：

1. 统一 GLB/FBX 导出适配器输入和烘焙流程。
2. 实现动作多选、角色组合清单、命名和冲突策略、导出预设。
3. 实现后台队列、逐项结果、取消、临时文件提交和失败重试。
4. 输出结果清单和语义事件清单；暴露批量导出工具。
5. 验证原地与保留位移两种输出，完成 UE 中的目标骨架导入与回放。

简单验收：选中两个角色与三个动作，明确生成六个组合；注入一个无效组合时其余有效项可完成，清单能准确显示失败原因。修改源动作后，正在导出的任务仍使用原快照，并在结果中标明版本。

### 1.9 P7：稳定与完整首版交付

交付任务：

1. 完善自动恢复、工程移动后的资源定位、格式版本提示和升级保留。
2. 检查目标硬件上的常规播放与时间轴交互，修复明确瓶颈。
3. 打包 Windows 软件、原生扩展、格式辅助组件及本地 MCP 适配器。
4. 提供简短安装说明、操作说明、接口样例、格式说明和已知限制。
5. 准备标准木偶、一个已有骨架角色、一个无骨骼角色及少量完整示例动作。

简单验收：在不启动 Godot 编辑器的环境中完成“制作 → AI 修改 → 两类角色适配 → 保存重开 → 批量导出 → UE 播放”。恢复一次未正常退出的编辑会话，并核对本地引用与导出结果清单。

## 2. 风险与处理决策

| 风险 | 对结果的影响 | 提前处理的位置 | 首版策略 |
| --- | --- | --- | --- |
| 独立应用导入导出与编辑器内表现不同 | 打包后不能使用真实角色 | P0 | 在打包应用中验证，避免只验证 Godot 编辑器 |
| FBX SDK 或转换组件不满足条件 | 无法交付 UE 动画 | P0 | 先验证并固定路线，核心与格式插件隔离 |

| 骨架变更未使缓存过期 | 显示或导出旧结果 | P1 起 | 骨架版本、文档修订和缓存键统一设计 |

| 预览与导出求解不同 | 软件内正确、UE 内错误 | P0 起 | 共用求解与格式中间数据，按采样时刻回读比较 |
| 过早实现全部高级功能 | 首版迟迟无法使用 | 全程 | 每阶段交付可运行结果，扩展目标独立安排 |

## 3. 开发启动清单

后续进入实现时，优先按以下顺序开始：

1. 创建独立 Godot 工程及不依赖引擎类型的 C++ 动画核心，固定版本与依赖。
2. 定义项目、骨架、时间码、动作、约束、绑定、适配和导出预设的数据契约。
3. 建立命令与撤销机制，在最小木偶上验证一次完整的姿势修改。
4. 验证带蒙皮测试角色的 GLB/FBX 输出与 UE 回读，再扩展界面。
5. 按 P1–P7 逐步交付，每阶段只进行与该阶段相关的简单验收。

代码规范沿用用户约定：新增函数、类型和属性添加中文注释；用户可见名称使用简短中文。若增加 UE 辅助类型，需要中文 DisplayName（显示名称）与 Category（分类），按实际用途隐藏无关编辑器属性，并对蓝图可调用接口提供中文说明。

本文的待冻结事项均安排在 P0：Godot 与扩展的准确版本、FBX 出口依赖、参考硬件、诊断阈值和构建脚手架。它们不影响当前功能范围；通过技术验证后记录决定及原因，再开始正式功能开发。
